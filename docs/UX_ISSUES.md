# 成章：使用体验问题记录

> 文档状态：使用中日志  
> 用途：在真实写作与日常捕捉中记录摩擦，供迭代排序；**不**等于版本承诺或技术方案。  
> 相关：[ALPHA_REQUIREMENTS.md](./ALPHA_REQUIREMENTS.md) · [POST_ALPHA_BACKLOG.md](./POST_ALPHA_BACKLOG.md) · [ALPHA_DESIGN_REVIEW.md](./ALPHA_DESIGN_REVIEW.md)

## 1. 怎么用这份文档

1. **边用边记**：遇到「卡住、犹豫、误触、看不懂、想骂」就记一条，不必等功能做完。  
2. **先事实后方案**：优先写「我当时想做什么 / 实际发生了什么 / 感受」，解决思路可后补。  
3. **一篇文章复盘一次**：写完或导出一篇后，用 §4 的复盘问题扫一遍，补漏记。  
4. **进开发前过一遍**：修体验时优先 P0/P1；可产品化的进版本需求或 [POST_ALPHA_BACKLOG](./POST_ALPHA_BACKLOG.md)。

### 严重程度（自用约定）

| 级别 | 含义 |
| --- | --- |
| **P0** | 无法继续写 / 丢内容 / 严重误导；当天或当前文章必须绕过或修 |
| **P1** | 明显打断思路或重复浪费时间；影响日常使用意愿 |
| **P2** | 别扭、啰嗦、不清晰；能忍但累积烦 |
| **P3** | 观感、措辞、细节；有空再收 |

### 状态

| 状态 | 含义 |
| --- | --- |
| `open` | 仍存在 |
| `mitigated` | 有临时绕过，未根治 |
| `fixed` | 已在产品中修好（可注明 commit / 版本） |
| `wontfix` | 接受现状或超出当前范围 |
| `moved` | 已迁到 backlog / 需求文档 |

## 6. 与其他文档的边界

| 文档 | 关系 |
| --- | --- |
| 本文 `UX_ISSUES.md` | 原始体验日志，允许粗糙、主观、重复 |
| `ALPHA_REQUIREMENTS.md` | 已承诺的 Alpha 功能与验收 |
| `POST_ALPHA_BACKLOG.md` | 候选能力；体验问题验证为「稳定重复」后再迁入 |
| `ALPHA_TECHNICAL_PLAN.md` | 怎么实现；本文不写实现细节除非有助于复现 |

从本文晋升时建议：

1. 确认是**重复出现**或**直接挡文章完成**；  
2. 写成可验收的需求或 backlog 条目；  
3. 在对应 UX 条目标 `moved`，并链到目标文档。
