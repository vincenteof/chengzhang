# 成章：使用体验问题记录

> 文档状态：使用中日志  
> 用途：在真实写作与日常捕捉中记录摩擦，供迭代排序；**不**等于版本承诺或技术方案。  
> 相关：[ALPHA_REQUIREMENTS.md](./ALPHA_REQUIREMENTS.md) · [POST_ALPHA_BACKLOG.md](./POST_ALPHA_BACKLOG.md) · [ALPHA_DESIGN_REVIEW.md](./ALPHA_DESIGN_REVIEW.md)

## 1. 怎么用这份文档

1. **边用边记**：遇到「卡住、犹豫、误触、看不懂、想骂」就记一条，不必等功能做完。  
2. **先事实后方案**：优先写「我当时想做什么 / 实际发生了什么 / 感受」，解决思路可后补。  
3. **一篇文章复盘一次**：写完或导出一篇后，用 §4 的复盘问题扫一遍，补漏记。  
4. **进开发前过一遍**：修体验时优先 P0/P1；可产品化的进版本需求或 [POST_ALPHA_BACKLOG](./POST_ALPHA_BACKLOG.md)。

### 严重程度（自用约定）

| 级别 | 含义 |
| --- | --- |
| **P0** | 无法继续写 / 丢内容 / 严重误导；当天或当前文章必须绕过或修 |
| **P1** | 明显打断思路或重复浪费时间；影响日常使用意愿 |
| **P2** | 别扭、啰嗦、不清晰；能忍但累积烦 |
| **P3** | 观感、措辞、细节；有空再收 |

### 状态

| 状态 | 含义 |
| --- | --- |
| `open` | 仍存在 |
| `mitigated` | 有临时绕过，未根治 |
| `fixed` | 已在产品中修好（可注明 commit / 版本） |
| `wontfix` | 接受现状或超出当前范围 |
| `moved` | 已迁到 backlog / 需求文档 |

## 3. 问题详情

### UX-001 — 初稿真正的流式 UI

- **日期**：2026-08-08
- **级别**：P2
- **状态**：open
- **类型**：UI/UX 迭代项（非当前功能缺口验收阻塞）
- **场景**：Idea 工作区 / 草稿页「AI 生成初稿」
- **我当时想做**：生成初稿时能看见文字逐渐出来，确认模型在干活、内容方向是否靠谱
- **实际发生**：服务端可 stream 收集，前端仍整段返回后再展示；等待期间只有简短状态文案，长请求像无响应
- **摩擦类型**：反馈缺失 · 性能体感 · 信任/AI
- **发生频率**：每次生成初稿
- **期望体验**：分片进入 suggestion buffer；可滚动预览；可取消；完成后再「接受/拒绝」写入正文（仍不自动改稿）
- **可能方向**：typed stream 或 SSE/Server Route；客户端 suggestion 区流式追加；取消信号贯通 Provider
- **关联**：FR-DRAFT-01 · ALPHA_TECHNICAL_PLAN Slice 3「初稿 typed stream」· AC-06 体验增强
- **备注**：基础生成/接受已可用；本项专做体验，不挡 Alpha 主闭环验收

### UX-002 — 选区 AI 更细粒度 diff

- **日期**：2026-08-08
- **级别**：P2
- **状态**：open
- **类型**：UI/UX 迭代项
- **场景**：草稿页 · 选区 AI（组织 / 补写 / 润色）
- **我当时想做**：看清 AI 改了哪些词句，再决定是否接受
- **实际发生**：接受前有「原文 / 建议」整段并排预览，但不是行级或词级 diff；长选区时难比对
- **摩擦类型**：认知负担 · 信任/AI · 反馈缺失
- **发生频率**：每次使用选区改写类 AI
- **期望体验**：在原文与建议之间有更细的差异高亮（至少行级，理想词/句级）；反馈类操作可不 diff
- **可能方向**：轻量 diff 库或自研行 diff；保留并排 + 高亮变更；接受后仍可一次撤销
- **关联**：FR-DRAFT-04 · ALPHA_TECHNICAL_PLAN Slice 4「suggestion diff」· AC-07 体验增强
- **备注**：选区 AI 接受/拒绝/stale 已可用；本项专做 diff 呈现细化

## 6. 与其他文档的边界

| 文档 | 关系 |
| --- | --- |
| 本文 `UX_ISSUES.md` | 原始体验日志 + **UI/UX 迭代队列**，允许粗糙、主观、重复 |
| `ALPHA_REQUIREMENTS.md` | 已承诺的 Alpha 功能与验收 |
| `POST_ALPHA_BACKLOG.md` | 候选**产品能力**；体验打磨优先记在本文，不必先扩 backlog |
| `ALPHA_TECHNICAL_PLAN.md` | 怎么实现；本文不写实现细节除非有助于复现 |

从本文晋升时建议：

1. 确认是**重复出现**或**直接挡文章完成**；  
2. 写成可验收的需求或 backlog 条目；  
3. 在对应 UX 条目标 `moved`，并链到目标文档。
